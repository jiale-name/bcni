## 0. 一句话结论

一期 = 需求 §0.3 的 **N1 应用基座 + 档案与数字画像模块**，形态为 **FastAPI（8002）+ Vue3 SPA（Nginx:80）+ MySQL 8.0 + Redis 7**，
AI 能力（解析 / 向量 / 检索 / 问答）由**可降级的外部组件**（Ollama / MinIO / Milvus / Dify）按能力逐级接入。

**客观核对（本次实测）**：`openapi.json` 路径数 **95** · 前端页面文件 **23** 个（chunk 46 = 23×2）· 路由三口径自洽 · Alembic 迁移 **14** 个且**单头无断链** · ORM 表 **40** 张。

## 4. 依赖关系

### 4.1 后端分层（🔴 只能向下，`test_layering.py` 机械守卫）

```
routers  →  services  →  dao  →  models
   ↓            ↓          ↓
 只声明绑定   业务/事务   纯 CRUD + 强制租户条件
        core/ 横切（被各层使用，不反向依赖业务）
        scripts/ → app/ 单向（禁止 app 反向 import scripts）
```

铁律：Router 不写业务判定；DAO 不写规则；跨库补偿顺序（MySQL ↔ Milvus）只在 Service。

### 4.2 运行期依赖矩阵（**部署时按此决定装什么**）

| 组件 | 用途 | 一期是否必须 | 缺失时的行为 | 端 |
| --- | --- | :-: | --- | --- |
| **MySQL 8.0** | 唯一权威关系库（40 表） | ✅ **必须** | 服务可启动但全部业务不可用（`/health` 返回 `code=50301` + `degraded=true`） | 3306 |
| **Redis 7** | 会话 / 限流 / 幂等 / 队列 / Agent 短期记忆 | ✅ **必须** | 抖动 fail-open；限流与幂等降级 | 6379 |
| **MinIO** | 简历原始文件对象存储 | 🟡 建议 | 回落本地 `data/uploads` 落盘（设计内兜底） | 9000/9001 |
| **Milvus 2.4** | 向量检索（+ etcd 元数据 + MinIO 后端） | ⬜ 可选 | 检索**自动降级**为关键词模式（`code=50302` + `degraded=true`） | 19530/9091 |
| **Ollama** | 本地 LLM（qwen2.5:3b 解析 / qwen3:8b 推理）+ bge-m3 向量 | ⬜ 可选 | 解析走确定性规则组件，AI 文本能力降级 | 11434 |
| **Reranker** | bge-reranker-v2-m3 重排 | ⬜ 可选 | 跳过重排，用 RRF 结果 | 9997 |
| **Dify** | 出网编排通道（可选） | ⬜ 可选 | 出网通道留空即禁用（合规默认） | 80/5001 |
| Nginx | 生产入口：托管 dist + 反代 /api | ✅ **生产必须** | — | 80 |

### 4.3 数据流（请求路径）

```
浏览器 → Nginx :80 ─┬─ /assets/* · /  → frontend/dist（静态）
                    └─ /api/*         → uvicorn :8002
                                          └→ routers → services → dao → MySQL
                                              ↑ core/ 中间件：CORS → TraceId → RequestMeta → RateLimit
                                              └→ 可选外呼：Ollama / Milvus / MinIO / Reranker / Dify
```

> 🔴 **同源是硬设计**：前端 `axios baseURL = /api/v1`，靠反代而非跨域 ⇒ 生产**不需要 CORS**（开发期因前端在 :5173 才开）。
