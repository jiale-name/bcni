# 简历解析问题修复说明

## 1. 问题范围

本次以用户提供的 PDF 简历作为只读复现样本，排查“上传后档案字段不完整/看起来没有解析出来”的问题。附件内容仅用于复现，没有复制到项目测试夹具，也没有把姓名、手机号、邮箱等个人信息写入代码或日志。

## 2. 根因定位

解析链路分为四步：

1. 按扩展名识别 PDF；
2. 优先读取 PDF 文字层；
3. 使用确定性规则抽取基础字段；
4. 将字段归一并写入人才档案。

复现结果表明，附件 PDF 的文字层可正常读取，共读取到 3015 个字符，读取来源为 `pdf_text_layer`。因此问题不是文件损坏，也不是必须依赖 OCR 的扫描件。

原规则存在两个布局缺口：

- 工作年限只匹配“4 年工作经验”这类数字在前的写法，无法匹配简历中的“工作时长：4 年”；
- 院校只匹配“毕业院校：xxx”这类显式标签，无法匹配教育背景常见的“起止年月 学校 学历”单行写法。

另外，PDF 文字层会把中文字符之间的排版空格抽出来，例如“工 作 时 长”。现有 `_fold_cjk_spaces` 会先折叠这类字间空格，这是必要的；但折叠后“河南理工大学 本科”会变成“河南理工大学本科”，时间轴规则因此必须允许学校和学历紧贴。

## 3. 修复内容

### 3.1 增加显式工作时长规则

新增规则支持以下形式：

```text
工作时长：4 年
工作年限: 4年
工作经验：4年
```

显式标签命中时置信度为 `0.85`；原有“4 年工作经验”等推断形式仍保留，置信度为 `0.65`。

### 3.2 增加教育时间轴规则

新增规则支持以下形式：

```text
2017.09—2022.06 河南理工大学 本科
```

规则要求完整的年月范围和受控学历词，降低把正文普通句子误识别为院校的风险。该形式没有显式“毕业院校”标签，因此院校置信度按推断值 `0.65` 处理。

规则同时处理“学校 本科”被中文空格折叠为“学校本科”的情况，并避免把“河南理工大学本科”错误截成“河南理工”。

### 3.3 保留安全边界

- 显式院校标签优先于教育时间轴推断；
- 学历仍使用原有学历词折叠与字典归一逻辑；
- 无法确认的字段不编造，继续进入低置信字段复核；
- 当前版本已补齐工作经历、项目经历的确定性结构化解析、导入落库和 API-31 详情装配；技能、证书明细仍未建模，本次没有伪造这些明细。

### 3.4 工作 / 项目经历结构化解析

新增章节级规则，支持工作经历与项目经历的多条明细。每条明细统一输出主体名称、角色/职位、起止日期、描述、技术栈和来源；工作经历额外输出部门和在职标记。

- 日期只有年月时，开始日期取当月 1 日，结束日期取当月最后一天；“至今 / 现在”取 `end_date = null`、`is_current = 1`；
- 明细按开始日期倒序重新编号 `seq_no`；相同主体、时间和角色的重复条目只保留一条；
- 空主体和无法确认的条目跳过，不编造公司或项目名称；技术栈按中文顿号、逗号、斜线和空白拆分为 JSON 数组。

### 3.5 导入事务与幂等

工作 / 项目明细在 `make_persist_callback` 中与 `talent_base` 使用同一数据库会话和事务，先写主档，再使用 DAO 替换 TBL-12/TBL-13 明细，最后更新文件状态与留痕。任一步抛错由上层文件事务统一回滚；命中 `import_file.talent_id` 时直接返回已有档案 ID，不重复建档或重复写入明细。

### 3.6 详情、合并和个人权利读路径

- API-31 `with_detail=true` 查询 TBL-12/TBL-13，并把 `position_name`/`role_name` 映射为前端契约的 `title`/`role`；`with_detail=false` 不查询明细。
- 查重合并按公司/职位/起止日期或项目名/起止日期去重；人工来源优先于 AI 来源，唯一明细迁移到主档，冲突明细软删除。
- 合并快照保存双方明细和版本号，API-61 回滚恢复原归属、字段、软删除状态和序号；API-71/79 的本人查阅与导出包含工作/项目明细。
- 技能和证书仍只返回空数组及 TBL-14/TBL-15 未建模说明。

## 4. 验证结果

新增两条回归测试：

- `test_work_years_accepts_labeled_duration_layout`
- `test_school_accepts_education_timeline_layout`

两条测试先在旧代码上失败，加入规则后通过。

对用户提供的 PDF 做真实只读探针，当前抽取结果包含：

- 姓名
- 手机号
- 邮箱
- 性别
- 工作年限
- 院校
- 学历

其中姓名、院校属于 PDF 排版布局推断，仍按现有置信度和人工复核机制处理；联系方式只在结果中用于入库加密/脱敏，不写入普通日志。
