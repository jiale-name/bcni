#请重点确认依据 / 影响
1 P-19「数据字典与系统配置」是否补入一期页面清单？
需求文档 §C.5 的「一期约 18 页」清单中没有这一页， 但 F-1.7 是一期 P0 功能点，且 API-23~27 需要页面承载 —— 属清单遗漏，建议补入。		 F-1.7 · API-23~27
清单不一致
2 导入单批上限（100 份）与单文件上限（50MB）是否需甲方书面确认？
Q-12。超限直接影响甲方实际使用体验，属验收口径； 建议值配置化，避免改代码。		 Q-12 · F-3.1
需确认
3 接口定义走「代码优先」还是「文档优先」？
Q-10。推荐代码优先：FastAPI 天然产出 OpenAPI， 用 openapi-typescript 生成前端 TS 类型；接口设计文档作为契约规范与评审依据。		 Q-10 · 接口设计 §7
4 档案问答是否需要 WebSocket / 长连接？
Q-11。一期 SSE 单向流足够；若需「边生成边追问」 或多端同步同一会话，需改协议。		 Q-11 · F-3.7
5 复核漏斗阈值（高影响面 0.85 / 低影响面 10% 抽样）是否按实际数据调整？
全量复核不可行（300 份 × 20 字段 × 30% ≈ 1800 次确认）。 阈值本身可配，建议首轮导入后按实际复核量回调。		 D-8 · F-3.3
6 出网边界是否与甲方书面确认？
若甲方要求「100% 不出网（含脱敏片段）」， F-3.7 必须改用本地模型（qwen3:8b），接受生成质量降级 + 追加 GPU 采购 —— 属成本与质量重大变更。		 Q-2 · §10.5
高风险
7 技术偏离申报（12 项）是否已进投标技术偏离表？
F-2/F-4/F-5/F-6/F-7/F-8/F-10 对应原文「必须落地」条款， 未如实申报可能被判实质性偏离废标。		 B-3 · §0.3.2
废标风险
8 视觉风格是否沿用本原型的「浅色简洁政务风」？
原型为对齐信息架构与主流程，非视觉稿。 正式前端视觉（含是否需要 AI 科技风）建议在 UI 设计阶段单独确认。		 原型规范 §一

本版未覆盖项明确边界，避免评审时被问住

① 后续阶段模块页面（⏸ 有意不做） —— F-2 企业知识库问答、F-4 智能测评、F-5 NL2SQL 问数、 F-6 岗位匹配、F-7 智能培训、F-8 Skills 编排、F-10 多端协同。
② 移动端 / 响应式（F-10.1，P2 规划项）；本原型按 1440px 桌面端设计。
③ 站内信 / 邮件通知页面（F-10.3）；仅在各页以文案形式提及「结果将通知您」。
④ 真实交互 —— 页面之间为相对链接跳转（可点通），但表单提交、弹窗、抽屉为静态示意， 不做真实接口调用。
⑤ 图表为手绘内联 SVG 示意（雷达图 / 成本柱状图），非 ECharts 真实数据； 正式前端用 ECharts，数据源见接口设计 API-34 / API-89。
⑥ 导出产物（Excel / PDF / 个人数据包）仅标注入口，不含真实文件生成逻辑。

使用与交付说明

零外部依赖：全部 CSS 内联，不引任何 CDN，断网可直接打开； 左侧导航与页面之间用相对链接互跳，可点通全站（需保持同目录）。
设计系统统一：全部 19 页共用同一套 :root 变量与通用 class （由 _gen_prototype.py 统一生成），避免各页各写一套配色。
标注约定：①②③ = 主流程点击顺序　🔒 = 需权限（旁注角色）　 <!-- STATE: xxx --> = 状态分区（每页底部）
与上游对齐：字段名、按钮文案、枚举取值与《需求分析文档 v1.3》《数据库设计 v1.0》 《接口设计 v1.0》用词一致 —— 原型与接口对不上，联调时必然打架。
假数据：全部使用真实感数据（李伟 / 数据治理部 / 硕士 / 6 年 / 简历_李伟.pdf / IMP20260921001）， 不使用 xxx、test1 之类占位符 —— 否则看不出字段长度与排版问题。
