> 版本：v1.1  
> 日期：2026-09-29  
> 基线：P-21～P-26 原型、数据库设计文档、架构设计文档

接口编号从现有 `API-095` 之后连续扩展为 `API-096~API-159`。一个接口对应一个 API 编号；不得为了压缩编号合并不同资源、权限或幂等语义的接口。

## 1. 通用协议

### 1.1 地址和响应

基础地址：`/api/v1`。所有业务接口返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "page": null,
  "trace_id": "tr_20260928_000001"
}
```

成功只看 `code == 0`。ID 统一以字符串返回，时间使用 ISO 8601；分页统一使用 `page_no`、`page_size`、`total`。

### 1.2 请求头和幂等

| Header | 要求 |
| --- | --- |
| `Authorization` | 登录态或服务端令牌 |
| `X-Tenant-Id` | 仅服务端可从认证上下文确定，客户端传入值只用于兼容校验 |
| `X-Org-Id` | 组织范围，必须经过权限校验 |
| `X-Request-Id` | 可选，服务端生成并回传 |
| `Idempotency-Key` | 创建、提交、发布、保存答案等写操作必填 |

### 1.3 错误码

| HTTP | `code` | 说明 |
| ---: | ---: | --- |
| 400 | `40001` | 参数校验失败 |
| 401 | `40101` | 未认证 |
| 403 | `40301` | 无权限或组织范围不匹配 |
| 404 | `40401` | 资源不存在或不可见 |
| 409 | `40902` | 并发版本冲突/幂等键冲突 |
| 422 | `42201` | 非法状态流转 |
| 422 | `42202` | 发布前校验不通过 |
| 423 | `42301` | 资源已锁定或已发布不可修改 |
| 429 | `42901` | 请求限流 |
| 500 | `50001` | 未分类服务错误 |
| 503 | `50301` | 依赖不可用或降级 |
| 502 | `50201` | 模型网关调用失败 |

## 4. 接口分组

### 4.1 题库和能力维度

#### `GET /assessment/dimensions`

返回启用能力维度、等级规则和排序。P-21、P-22 的下拉选项都来自该接口。

#### `GET /assessment/questions`

查询参数：

```text
page_no, page_size, keyword, question_type, dimension_code,
source_type, review_status, enabled_status, sort_by, sort_order
```

返回 `items` 至少包含：`id`、`question_code`、`question_version`、`stem_summary`、`question_type`、`dimensions`、`difficulty`、`source_type`、`review_status`、`enabled_status`、`updated_at`、`available_for_paper`。

#### `POST /assessment/questions`

请求体：`stem`、`question_type`、`options`、`answer_key`、`rubric`、`difficulty`、`max_score`、`dimensions`、`source_type`。创建为 `draft`，不自动启用。

#### `PUT /assessment/questions/{id}`

只允许更新草稿版本；已审核版本只能创建新版本。必须携带 `row_version`，冲突返回 `40902`。

#### `POST /assessment/questions/{id}/review`

请求体：`decision`、`comment`。`decision` 为 `approve` 或 `reject`。AI 生成题目审核时必须确认题干、答案和能力维度。

### 4.2 试卷和题目池

#### `GET /assessment/papers/{id}/question-pool`

查询参数：`keyword`、`dimension_code`、`question_type`、`difficulty`、`page_no`、`page_size`。只返回审核通过且启用的题目；待审核题目必须返回 `available_for_paper=false` 和原因。

#### `POST /assessment/papers/{id}/questions`

请求体：`question_id`、`score`、`expected_seq_no`。服务端重新校验题目状态、试卷状态和维度配额。

#### `POST /assessment/papers/{id}/validate`

返回：`errors`、`warnings`、`total_score`、`dimension_distribution`、`snapshot_ready`。存在 `errors` 时不能发布；只有 warning 可以由有权限的 HR 确认后继续。

#### `POST /assessment/papers/{id}/publish`

服务端生成题目、维度、答案规则和随机种子快照，使用幂等键保证重复发布不产生新版本。

### 4.3 任务和作答

#### `POST /assessment/tasks`

请求头：必须携带 `Idempotency-Key`。请求体严格为 `AssessmentTaskCreateRequest`：

```json

  "paper_id": "9001",
```

约束：`mode` 只能为 `explicit`；`candidates` 必须为数组且至少一项；每项的三个 ID 必须能转换为 `BIGINT UNSIGNED`，并在服务端通过租户和 `DataScopeFilter` 校验。`org_id` 不从任务请求单独接收，任务组织从认证上下文确定。`task_code` 由服务端生成，客户端不得传入。创建成功后的任务状态为 `draft`。当 `notify_on` 包含 `task_created` 时，服务端为每个已分配候选人和每个配置渠道写入 `assessment_notification(status=pending, notification_type=task_created)`；不调用外部发送渠道。

#### `POST /assessment/tasks/{id}/activate`

请求头：必须携带 `Idempotency-Key`。请求体为：

```json
{"row_version": 1}
```

激活前必须同时满足：任务存在且在当前租户和组织范围内可见；当前状态为 `draft`；关联试卷已发布；`target_scope.mode=explicit` 且结构合法；至少存在一条合法的 `assessment_task_candidate`；候选人不重复、候选人组织范围通过服务端校验；`start_at < deadline_at`、`duration_min > 0`、`attempt_limit >= 1`；`notify_rules` 合法，且其中已配置的通知规则可映射为允许的通知记录。候选人记录缺失时禁止激活，不自动补齐或绕过分配记录。

#### `POST /assessment/tasks/{id}/remind`

请求头：必须携带 `Idempotency-Key`。本批只支持显式候选人分配，不解析部门或岗位范围。请求体为：

```json
{
  "candidate_ids": ["7001", "7002"],
  "channels": ["in_app", "email"]
}
```

`candidate_ids` 为 `assessment_task_candidate.id`，省略或传空数组表示任务当前全部有效候选人；`channels` 至少一项且只能是 `in_app` 或 `email`。服务端必须校验候选人属于任务、候选人记录在调用者数据范围内，且请求不能扩大组织范围。每个候选人和渠道写入一条 `assessment_notification(status=pending, notification_type=reminder)`；重复幂等请求返回原通知记录，不真实发送通知。

#### Attempt 契约冻结补充（人工决策）

本补充冻结 API-131～API-139 的处理规则，不新增接口。

1. API-131 首次请求创建 Attempt；已有 `in_progress` Attempt 时返回已有 Attempt，不创建新记录且不增加 `attempt_count`；已有终态 Attempt 时按 `attempt_limit` 判断是否允许创建下一次。开始请求使用服务端时间，并生成 `paper_snapshot`、`duration_min_snapshot`、`deadline_at_snapshot`、`attempt_no`。
2. API-131 的 Candidate 次数更新与 Attempt 创建必须同一事务完成：锁定 Candidate 行，校验 `attempt_count < attempt_limit`，生成 `attempt_no`，递增 `attempt_count`，再创建 Attempt。`attempt_count` 是任务级次数校验依据。
3. API-132/133 不得从实时题库读取已创建 Attempt 的题目内容；API-133 读取 API-131 生成的 TBL-33 快照。快照至少包含题目 ID、题目版本、题型、题干、选项、选项顺序、分值和题目顺序，以及文档已定义的其他快照字段。
3.1 Attempt 在业务语义上绑定 API-131 创建时任务所关联的已发布 Paper `version_no`；该版本是本次测评完整评分上下文版本。此规则不新增 API-131 请求/响应字段，不改变当前 `paper_snapshot` schema，具体冻结数据承载方式留待后续实现阶段。
4. API-134 的 `answer_version` 从 `0` 开始。客户端首次携带 `0`，服务端校验成功后将当前 `assessment_answer` 写入/更新为版本 `1`，并将 Attempt 版本更新为 `1`；后续携带当前版本 `N`，成功后更新同一答案记录为 `N+1`。冲突返回 `40902`，不得覆盖并发更新，不保存无限历史答案。
5. API-138 只有 `confirm=true` 才能正式提交。服务端锁定 Attempt，校验 `status=in_progress`，执行提交前检查、冻结答案、写提交时间、设置 `submitted`、更新 Candidate 并写入评分任务 Outbox 事件。重复主动提交必须返回同一提交结果，不得重复写入评分任务 Outbox 事件。API-138 与超时 Worker 并发时以数据库状态锁保证只有一个提交结果生效。
6. 超时由后台 Worker 依据服务端时间 `server_now >= deadline_at_snapshot` 触发，且只允许 `in_progress -> auto_submitted`。自动交卷复用主动提交的答案冻结、提交时间、评分任务创建和 Candidate 更新原则。
7. API-139 中 `Idempotency-Key` 是 HTTP 请求级幂等，`client_event_id` 是客户端事件级幂等。唯一作用域为 `tenant_id + attempt_id + client_event_id`；二者不一致不视为冲突。重复事件不创建新事件，返回首次创建的 `event_id`，不产生重复事件副作用。TBL-37 的 `client_event_id` 为 VARCHAR(64) NOT NULL。

Attempt 状态仅允许 `not_started`、`in_progress`、`submitted`、`auto_submitted`、`cancelled`；后三者为终态，禁止新增状态。Candidate 联动固定为：API-131 设置 `assignment_status=started`、`attempt_count+1`、`progress=0`；API-134 只更新 `progress`；API-138 设置 `assignment_status=submitted`、`progress=100`；自动交卷设置 `assignment_status=submitted`、`progress` 按最终答案计算；`deadline_at` 按冻结规则保持不变。不得新增 Candidate 字段。

TBL-35 数据层最终冻结为数据库设计文档定义的 15 个字段，不增加 `org_id`、`created_at`、`created_by`、`updated_at`、`updated_by`、`row_version`、`deleted_at` 或其他字段。物理约束和索引仅包括 `uk_attempt_task_user_no(task_id, user_id, attempt_no)` 与 `idx_attempt_task_status_saved(task_id, status, last_saved_at)`；不使用条件唯一索引或状态辅助字段。`(task_id, user_id, status)` 仅作为查询优化建议。

同一 `task_id + user_id` 同时只能存在一个 `status=in_progress` 的 Attempt。API-131 由服务端锁定对应 Candidate，在同一事务中查询现有 `in_progress` Attempt；存在则返回已有 Attempt，不存在才创建新 Attempt。

#### API-131～API-139 完整 Request/Response Schema

以下 Schema 均使用通用响应封装 `{code,message,data,page,trace_id}`。成功时 `code=0`；ID 为字符串；时间为 ISO 8601。除特别说明外，所有接口均要求 `Authorization`，并由服务端从当前主体、租户和组织范围执行 DataScopeFilter。错误响应不返回业务成功数据。

##### API-131 开始作答

- **HTTP/Path**：`POST /api/v1/assessment/attempts`。
- **Request**：请求体 `task_id`，string，必填，非空且可转换为正的 BIGINT UNSIGNED；Header `Idempotency-Key`，string，必填。无 query/path 参数。
- **Response data**：`attempt_id` string 必填；`task_id` string 必填；`status` 固定为 `in_progress`；`attempt_no` unsigned integer 必填；`answer_version` unsigned integer，初始为 0；`server_now` ISO 8601 必填；`duration_min_snapshot` unsigned integer 必填；`deadline_at` ISO 8601 必填，值为 `deadline_at_snapshot`；`question_navigation` object 必填：`current_question_id` string、`total_questions` unsigned integer、`answered_count` unsigned integer、`questions` array；数组项为 `question_id` string、`question_order` unsigned integer、`answered` boolean。另返回 `saved_answers` array，项包含 `question_id` string、API-134 定义的 `answer` 对象和 `answer_version` unsigned integer。响应中不返回可用于作弊的标准答案。业务上该 Attempt 已绑定创建时 Paper `version_no`，但本响应不新增 Paper version 或 `rule_version` 字段。
- **空值**：上述标量和 `question_navigation` 不得为 null；无题目时 `questions=[]`，无已保存答案时 `saved_answers=[]`；`answer.value` 可为 null。
- **错误码**：`40001` 参数非法；`40101` 未认证；`40301` 非本人/越权；`40401` 任务或候选人分配不存在/不可见；`40902` 幂等冲突；`42201` 任务状态、时间窗口或次数不允许开始。
- **幂等/权限/DataScope**：同一 `Idempotency-Key` 返回首次成功结果；已有 `in_progress` Attempt 时返回该 Attempt，不创建新记录、不增加 `attempt_count`。DataScope 为当前 EMP 本人任务及其 Candidate 记录，权限为 `assessment:attempt:take`。

##### API-132 尝试详情

- **HTTP/Path**：`GET /api/v1/assessment/attempts/{id}`。
- **Request**：path `id`，string，必填，正 BIGINT UNSIGNED；无请求体、无 query；不要求 `Idempotency-Key`。
- **Response data**：`attempt_id` string 必填；`task_id` string 必填；`attempt_no` unsigned integer 必填；`status` 为五个冻结状态之一；`answer_version` unsigned integer 必填；`started_at` ISO 8601，可为 null；`duration_min_snapshot` unsigned integer 必填；`deadline_at_snapshot` ISO 8601 必填；`submitted_at` ISO 8601，可为 null；`server_now` ISO 8601 必填。
- **空值**：仅 `started_at`、`submitted_at` 可为 null；其余字段不得为 null。
- **错误码**：`40101`、`40301`、`40401`；Attempt 已进入终态时仍返回详情，不视为错误。
- **幂等/权限/DataScope**：GET 可重复读取；仅允许 `assessment:attempt:take` 范围内的本人 Attempt，按租户、组织和本人 Candidate 关系过滤。

##### API-133 题目快照

- **HTTP/Path**：`GET /api/v1/assessment/attempts/{id}/questions`。
- **Request**：path `id` 必填 string；query `page_no`、`page_size` 均为可选 integer，默认值和最大值沿用通用分页协议；不要求 `Idempotency-Key`。
- **Response data**：`page` 必须包含 `page_no`、`page_size`、`total`；`items` array 每项包含 `question_id` string、`question_version` unsigned integer、`question_type` string、`content` string、`options` array、`score` number、`question_order` unsigned integer、`answer_summary` object。每个 `options` 项包含 `code` string、`text` string、`order` unsigned integer；`answer_summary` 包含 `answered` boolean 和 `answer` 对象，`answer.value` 可为 string、number、boolean、array 或 null。
- **空值**：题目字段、`options`、`answer_summary` 不得为 null；无题目时 `items=[]`；空答案使用 `{`value`:null}`。
- **错误码**：`40101`、`40301`、`40401`、`40001`。不得从实时题库补取快照内容。
- **幂等/权限/DataScope**：GET 可重复读取；仅允许当前 EMP 读取本人 Attempt 的快照，权限为 `assessment:attempt:take`。

##### API-134 保存答案

- **HTTP/Path**：`PUT /api/v1/assessment/attempts/{id}/answers/{paper_question_id}`。
- **Request**：path `id`、`paper_question_id`，string，必填；body `answer` 必须为 `{`value`:...}`，对象本身必填且不得为 null，`value` 可为 string、number、boolean、array 或 null；`answer_version` unsigned integer，必填，首次为 0；`client_saved_at` ISO 8601，可选，可为 null，仅作展示/诊断；Header `Idempotency-Key` string，必填。
- **Response data**：`attempt_id` string 必填；`paper_question_id` string 必填；`answer_version` unsigned integer 必填，为保存后的当前答案新版本（首次成功保存为 `1`）；`saved_at` ISO 8601 必填；`progress` integer 必填，范围 0～100，为服务端计算并已保存的 Attempt progress。
- **空值**：`client_saved_at` 可为 null；其他已列字段不得为 null。
- **错误码**：`40001`、`40101`、`40301`、`40401`、`40902`（版本冲突或同一幂等键请求不一致）、`42201`（Attempt 非 `in_progress`）。旧版本请求不得覆盖并发更新。
- **幂等/权限/DataScope**：同一 `Idempotency-Key` 的同一请求返回首次保存结果；服务端仍必须校验 `answer_version`，成功后更新同一 `assessment_answer` 当前记录并将 Attempt 版本加一，不创建历史 answer 行。仅允许本人当前 Attempt 和题目快照，权限为 `assessment:attempt:take`。

##### API-135 作答提醒

- **HTTP/Path**：`GET /api/v1/assessment/attempts/{id}/reminders`。
- **Request**：path `id` string，必填；无请求体、无 query；不要求 `Idempotency-Key`。
- **Response data**：`attempt_id` string 必填；`notifications` array 必填。每项仅返回 `notification_id` string、`notification_type` string、`status` enum（`pending`/`sent`/`failed`）。
- **空值**：`notifications` 不得为 null，无记录时返回空数组；通知项三个字段均不得为 null。TBL-45 未定义通知创建时间，因此本接口不返回 `created_at`，也不以 `sent_at` 或 ID 推导创建时间。
- **错误码**：`40101`、`40301`、`40401`。
- **幂等/权限/DataScope**：GET 可重复读取；只读取当前 EMP 本人 Attempt 关联的通知，权限为 `assessment:attempt:take`。

##### API-136 作答进度

- **HTTP/Path**：`GET /api/v1/assessment/attempts/{id}/progress`。
- **Request**：path `id` string，必填；无请求体、无 query；不要求 `Idempotency-Key`。
- **Response data**：`total_questions` unsigned integer 必填；`answered_count` unsigned integer 必填；`unanswered_count` unsigned integer 必填；`progress` integer 必填，范围 0～100；`current_question_id` BIGINT UNSIGNED，可为 null；`last_saved_at` ISO 8601，可为 null；`deadline_at` ISO 8601 必填；`server_now` ISO 8601 必填。
- **空值**：除 `current_question_id`、`last_saved_at` 外不得为 null；无答案时 `answered_count=0`、`progress=0`；无当前题目时 `current_question_id=null`，不得使用 0、空字符串或伪造 question_id 代替 null；存在当前题目时返回对应的 BIGINT UNSIGNED `question_id`。
- **错误码**：`40101`、`40301`、`40401`、`42201`（Attempt 状态不允许读取进度时）。
- **幂等/权限/DataScope**：GET 可重复读取；进度必须基于服务端答案和 Candidate 权威字段计算，不接受客户端统计值，权限为 `assessment:attempt:take`。

##### API-137 提交前检查

- **HTTP/Path**：`POST /api/v1/assessment/attempts/{id}/submit/check`。
- **Request**：path `id` string，必填；无请求体；该接口不改变状态，不要求 `Idempotency-Key`。
- **Response data**：`can_submit` boolean 必填；`unanswered_count` unsigned integer 必填；`unanswered_questions` array 必填，项包含 `question_id` string、`question_order` unsigned integer；`server_now` ISO 8601 必填；`deadline_at` ISO 8601 必填；`timeout` boolean 必填；`blocking_reasons` array[string] 必填。
- **空值**：`unanswered_questions`、`blocking_reasons` 不得为 null，无内容时为空数组；其他字段不得为 null。
- **错误码**：`40001`、`40101`、`40301`、`40401`、`42201`（Attempt 不在可检查状态）。
- **幂等/权限/DataScope**：同一状态下可重复调用且不产生副作用；只检查本人 Attempt，权限为 `assessment:attempt:take`。

##### API-138 主动作答提交

- **HTTP/Path**：`POST /api/v1/assessment/attempts/{id}/submit`。
- **Request**：path `id` string，必填；body `confirm` boolean，必填且必须为 true；Header `Idempotency-Key` string，必填。
- **Response data**：严格只返回 `attempt_id` string、`status` 固定为 `submitted`、`submitted_at` ISO 8601、`outbox_event_id` string；上述字段均必填，`outbox_event_id` 表示评分任务 Outbox 事件已可靠写入。不返回 `agent_task_id`，API-138 不等待评分 Worker 或 Agent 实际执行完成。
- **空值**：成功响应上述字段不得为 null；不返回 `auto_submitted` 作为 API-138 的成功状态。
- **错误码**：`40001`、`40101`、`40301`、`40401`、`40902`、`42201`（非 `in_progress`、提交检查不通过或 `confirm` 不满足）、`50301`（Outbox 写入依赖不可用）。Outbox 写入失败时整个事务回滚，不返回提交成功。
- **幂等/权限/DataScope**：锁定 Attempt 并以状态条件提交；答案冻结、Attempt 状态更新和评分任务 Outbox 事件写入同一数据库事务。评分 Outbox 固定为 `event_type=assessment.score.requested`、`aggregate_type=assessment_attempt`，payload 严格包含 `attempt_id`、`task_id`、`tenant_id`、`answer_version`，幂等键为 `attempt_id:score:v{answer_version}`；本轮不修改该 payload。后续评分流程必须通过 Attempt 创建时绑定的 Paper `version_no` 取得 `assessment_score.rule_version`，不得读取当前最新 Paper。相同 `Idempotency-Key` 重复提交返回首次成功结果，不重复冻结答案或写入评分任务；不同 `Idempotency-Key` 提交已为 `submitted` 的 Attempt 返回 `40902`。仅允许本人 Attempt，权限为 `assessment:attempt:take`。API-138 只能执行 `in_progress -> submitted`，不负责触发自动交卷；Worker 以 `server_now >= deadline_at_snapshot` 独立处理 `in_progress -> auto_submitted`。`submit_after_deadline` 仅作为事件类型，不参与 API-138 状态转换。

##### API-139 作答监控事件

- **HTTP/Path**：`POST /api/v1/assessment/attempts/{id}/events`。
- **Request**：path `id` string，必填；body `event_type` enum（`visibility_hidden`/`paste`/`idle`/`refresh`/`submit_after_deadline`/`device_change`）必填；`occurred_at` ISO 8601 必填，仅作参考；`duration_ms` unsigned integer 可选，可为 null；`metadata_summary` JSON object 必填，不得为 null且不得包含剪贴板/音视频原文；`client_event_id` string 必填，不得为空；Header `Idempotency-Key` string，必填。
- **Response data**：`event_id` string 必填。重复 `tenant_id + attempt_id + client_event_id` 返回首次创建的 `event_id`，不创建新事件且不产生重复副作用；不同 `Idempotency-Key` 携带相同事件标识时同样返回首次 `event_id`。
- **空值**：仅 `duration_ms` 可为 null；其余字段不得为 null。
- **错误码**：`40001`、`40101`、`40301`、`40401`、`40902`（HTTP 请求幂等键对应请求内容冲突或并发冲突）、`42201`（事件类型不允许）。`Idempotency-Key` 与 `client_event_id` 不一致不视为冲突。
- **幂等/权限/DataScope**：`Idempotency-Key` 负责 HTTP 请求级幂等，`client_event_id` 负责客户端事件级幂等；唯一作用域固定为 `tenant_id + attempt_id + client_event_id`。仅允许本人 Attempt，权限为 `assessment:attempt:take`。

API-139 不接收 `severity` 或 `review_status`。服务端按 `event_type` 显式生成 `severity`：`refresh=low`、`idle=low`、`visibility_hidden=medium`、`paste=medium`、`device_change=high`、`submit_after_deadline=critical`；创建时固定 `review_status=unreviewed`，并显式写入服务端 `received_at`。成功响应严格为 `{"event_id": "123456"}`，不返回 `received_at`、`severity`、`review_status` 或 `metadata_summary`。

##### TBL-37 `assessment_event` 字段契约

`assessment_event` 严格只有 13 个字段：`id` BIGINT UNSIGNED PK NOT NULL；`tenant_id`、`attempt_id` BIGINT UNSIGNED NOT NULL；`client_event_id` VARCHAR(64) NOT NULL；`event_type` VARCHAR(32) NOT NULL；`occurred_at`、`received_at` DATETIME(3) NOT NULL；`duration_ms` INT UNSIGNED NULL；`metadata_summary` JSON NOT NULL；`severity` VARCHAR(16) NOT NULL；`review_status` VARCHAR(24) NOT NULL；`reviewed_by` BIGINT UNSIGNED NULL；`reviewed_at` DATETIME(3) NULL。`event_type` 枚举为 `visibility_hidden`、`paste`、`idle`、`refresh`、`submit_after_deadline`、`device_change`；`severity` 枚举为 `low`、`medium`、`high`、`critical`，服务端映射为 `refresh=low`、`idle=low`、`visibility_hidden=medium`、`paste=medium`、`device_change=high`、`submit_after_deadline=critical`；`review_status` 枚举为 `unreviewed`、`reviewed`、`escalated`，API-139 创建时固定为 `unreviewed`。所有字段均无数据库默认值，不使用 `CURRENT_TIMESTAMP`。唯一约束为 `uk_attempt_client_event(tenant_id, attempt_id, client_event_id)`，普通索引为 `idx_attempt_event_received(attempt_id, received_at, event_type)`，不创建 `(attempt_id, occurred_at, event_type)` 索引。TBL-37 不增加公共字段、`server_received_at`、`event_status` 或 `event_payload`，不创建物理 ForeignKey；这些数据库字段不新增 API 请求字段，API-139 只接收本 Schema 已定义的事件字段。

### 4.4 监控

#### `POST /assessment/attempts/{id}/events`

请求体：`event_type`、`occurred_at`、`duration_ms`、`metadata_summary`、`client_event_id`。只接收允许的事件类型；服务端不保存剪贴板原文和音视频原文。

#### `GET /assessment/monitoring/results`

查询参数：`task_id`、`keyword`、`status`、`anomaly_only`、`page_no`、`page_size`。返回候选人、作答状态、完成率、异常数、报告状态和可执行操作。

#### `POST /assessment/events/{id}/review`

请求体：`decision`、`comment`。`decision` 为 `reviewed`、`escalated` 或 `dismissed`。该接口不直接修改分数。

### 4.5 报告和证据

#### `GET /assessment/reports/{id}`

返回：报告状态、候选人、总分、维度分、优势、短板、建议、发布信息、待复核项和版本信息。每条结论必须带 `evidence_ids`。

#### `POST /assessment/reports/{id}/reviews`

请求体：

```json
{
  "review_type": "subjective_score",
  "answer_id": "123456",
  "final_score": 12,
  "comment": "回答已覆盖冲突识别和协同动作。",
  "row_version": 2
}
```

服务端记录旧值、新值、操作者和理由；没有 comment 的人工改分请求拒绝。

#### `GET /assessment/reports/{id}/evidence`

返回 `evidence_id`、题目编号、答案摘要、维度、引用、分数快照、来源和确认状态。`unsupported` 证据必须标记为不可发布。

#### `GET /assessment/reports/{id}/publish-check`

返回 `can_publish`、`blocking_reasons`、`pending_reviews`、`missing_evidence`、`sync_warning`。前端按钮状态只能作为展示，最终以发布接口再次校验为准。

#### `POST /assessment/reports/{id}/publish`

校验证据完整、主观题已确认、高影响结论已复核、报告处于可发布状态后，生成不可覆盖发布快照并写审计。画像同步失败不回滚报告发布，转入补偿队列。

## 5. 状态和页面展示映射

| 后端状态 | 页面展示 |
| --- | --- |
| `draft` | 草稿、可编辑 |
| `pending_review` | 待审核/待复核 |
| `published` | 已发布 |
| `evidence_incomplete` | 证据不足、发布禁用 |
| `waiting_review` | 等待 HR 复核 |
| `returned` | 已退回，需要补充 |

通用页面状态为 `loading / empty / error / forbidden / conflict`，仅在页面适用时要求覆盖；不适用状态不强行增加。在线作答的 `reconnecting / expired / submitted / auto_submitted`、报告的 `evidence_incomplete / waiting_review / published / superseded` 等属于业务状态，按页面单独处理。

## 6. OpenAPI 和契约测试要求

1. 每个接口必须有请求 schema、响应 schema、错误码和权限声明。
2. 接口文档中的字段必须能映射到数据库字段或明确的聚合字段。
3. P-21～P-26 每个操作至少有一个接口契约测试。
4. 每批开发完成后导出 OpenAPI 快照，下一批不得无说明破坏上一批接口。
5. 前端联调禁止使用页面硬编码统计数据替代后端响应；原型数据仅用于 mock fixture。
