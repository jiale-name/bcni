### 关键技术决策（后续不得随意变更）
1. **统一同步驱动**：SQLAlchemy 同步 Session + 同步 Redis，路由用 `def`（FastAPI 交线程池）。
   理由：避免 async 事件循环被阻塞；Alembic 与业务共用同一套引擎配置。SSE/流式（N2/N5）才用 `async def` + `run_in_threadpool`。
2. **Alembic 连接串唯一来源 = `app.config.settings`**（`alembic.ini` 里 `sqlalchemy.url` 故意留空）。
3. **迁移链支持离线生成**：`alembic upgrade head --sql` 不连库即可产出 DDL → 无库环境也能评审/CI 校验。
4. **雪花 ID 三层防护**（CR-5）：`SnowflakeId = Annotated[int, PlainSerializer(str, when_used="json"), WithJsonSchema({"type":"string","format":"int64"})]` → Schema 层 + 真实 FastAPI 路由层 + 请求侧（string/number 都接受）。
5. **Token 吊销用 `token_dao`**：① 单 Token 否定名单 `sess:revoked:<jti>`；② 用户级全量失效用**单调递增的 Token 版本号** `sess:tok_ver:<tid>:<uid>`（Token 带签发时 `ver`，`ver < 当前版本` 即失效），调用点为 API-06 改密与 API-03 `all_devices=true`。**Redis 不可用时 fail-open + 告警**（不把 Redis 抖动升级为全站 401）。
   - ⚠️ **踩坑（本次自查发现并修正）**：最初实现为「记录 `logout_at` 时间戳 + 比较 JWT 的 `iat`」，但 `iat` 只有**秒级**精度 —— 「改密后同一秒内重新登录」会**误杀新 Token**，旧 Token 也可能漏判。已改为版本号方案，并用「同一秒内连续两次失效」的用例（`tests/test_token_dao.py`）钉死该场景。
6. **多角色数据域合并 = 取最宽**（数值最小 = 范围最大），理由是 RBAC 权限为并集语义。若改为「最小权限优先」只需改 `AuthService._resolve_data_scope` 一个函数。
7. **`snowflake.py` 重构**（本次）：新增可注入 `clock` + `max_backwards_ms`；小回拨改为「沿用上一毫秒 + 推进序列号」而**不再自旋等待**（原实现在冻结时钟下会死循环，不可测）。
8. **`DB_CONNECT_TIMEOUT=5`**（新增配置）：默认 10s 会让 `/health` 探针与启动自检很慢。

### 🔴 环境实测踩坑（4 条，均已修复并写入 README §8 排障手册）
1. **Redis 5.0.14.1 + redis-py 8.x 不兼容**：redis-py 8 默认 **RESP3**，连接先发 `HELLO 3`；而 `HELLO` 是 Redis 6.0 才有的命令 → 报 ``unknown command `HELLO```，现象是「Redis 进程活着但应用连不上」。
   - ✅ 修复：新增配置 **`REDIS_PROTOCOL=2`**，`redis_client.py` 强制 RESP2（本项目不需要 RESP3 推送；国产化/Windows 版 Redis 多为旧版）。
   - 附带：`encoding_errors="replace"` —— 部分中文 Windows 版 Redis 的 `INFO` 返回 GBK 文本，严格 UTF-8 解码会崩。并新增 `server_version()` 供 `/health` 展示版本，便于一眼区分「服务没起」与「版本不兼容」。
2. **MySQL 已启动但 root 需密码**（`Access denied ... using password: NO`）→ **需人工执行**：`cp .env.example .env` 填 `MYSQL_PASSWORD`，再 `alembic upgrade head`。**未替他猜测/写入密码。**
3. **`alembic.ini` 必须纯 ASCII**：Alembic 用 `configparser` 以 `encoding="locale"` 读取，中文 Windows 的 locale 是 GBK → ini 含中文即在启动前抛 `UnicodeDecodeError`（**实测踩到**）。已把中文说明移到 `alembic/README.md`。
4. **FastAPI 0.141 两个变更**：① `ORJSONResponse` 已弃用（带 `response_model` 的接口改由 Pydantic 直接序列化）→ 已移除；② `include_router` **不再把子路由摊平进 `app.routes`**（保留 `_IncludedRouter` 包装）→ 路由断言改为读 **OpenAPI**（版本无关）。
5. **JWT 密钥长度**：PyJWT 对 <32 字节的 HS256 密钥报 `InsecureKeyLengthWarning` → 默认占位密钥加长到 75 字节（`DEV_JWT_SECRET_PLACEHOLDER`），生产替换告警改为比对该常量。

### CU-08 审计日志（TBL-28 + API-28/29）
- **「只追加」三层结构保证**：① 模型无 `is_deleted`/`updated_at`；② DAO 只导出 insert/list/count + `__all__` 钉死；
  ③ 库级仅 INSERT/SELECT（**未做 → 遗留 CU-24**）。
- **复合主键 `(id, created_at)` 不是设计选择** —— MySQL 要求分区列进每个唯一键，`id` 单主键时
  `PARTITION BY RANGE` 直接建不了表。副作用：`created_at` 不可 UPDATE（审计表上是优点）。
- **写入 = 独立 Session + fail-open（永不抛）**：共用 Session 时业务回滚会**带走审计记录**，
  而最该留痕的恰是失败事件；审计写失败也不该把已成功的业务变 500。调用点**一律在业务 commit 之后**。
- **脱敏在写入侧**（键名黑名单递归：password/token/jwt/authorization/apikey/aes/encrypt/sign_key…），
  超长/过深截断；用户快照不含 PII 明文（只记 `has_phone`/`has_email`）。
- **导出返回 CSV 文本**（非文件流，否则丢掉统一响应 `code`/`trace_id`）；**超限直接 40002，绝不截断**。
- **CSV 公式注入防护**（`ua` 客户端可控，`=`/`+`/`-`/`@` 开头前置单引号）+ BOM + CRLF。
- 落库调用点 **10+ 处**：auth(login/logout/change_password) · dict(create/update/disable) ·
  rbac(role_create/update/perm_bind，含 granted/revoked 差集) · org(dept/position) · user_admin(create/update/role_assign/import)。
- **API-26 留痕确认改走 TBL-28**（上游指向的 `talent_change_log` 有 `talent_id NOT NULL`，字典项落不进去）。

### CU-09 限流接线

  CORS 最外层（429 要有 CORS 头，否则浏览器拦掉→**真因被掩盖**）。

### 新增环境实测结论

🔴 **MySQL `DATETIME`（无小数秒）对亚秒值四舍五入**：`…00.1→…00`、`…00.499999→…00`、

处置：测试侧统一 `.replace(microsecond=0)`；docstring 写明 1 秒级可见性延迟，

## 批次 9 · 迁移控制项落地（同日追加）

**用户指令**：「本轮继续沿用自研 Runtime，同时**补齐迁移控制项**，尤其是**副作用不能放在 interrupt 之前**，
避免恢复执行导致重复副作用。以后如果业务真正出现子图、复杂并行、状态历史等需求，再评估把 Graph 执行层逐步迁移到 LangGraph。」

### 做法：把「文档纪律」升级为「机械守卫」

判断：这条红线的失效方式**不是被人反对，而是被人忽略** —— 它在自研运行时下**今天不产生任何可观测故障**，
所以「写了注释」与「没写注释」当期跑起来完全一样；等切换那天才暴露，代价是**重复写库 / 重复计费**。
⇒ **能在装配期拦住的，就不要只写在文档里。**

三层落地：

| 层 | 落地物 | 拦什么 |
| --- | --- | --- |
| **装配期** | `GraphDefinition.interrupts` / `.side_effects` 声明 + `validate()` **互斥校验**（`__post_init__` 自动调用） | 「中断节点被声明为有副作用」→ **构造即抛 `NodeError`**。因 `registry` 在**导入时**构图 ⇒ 坏声明**让进程起不来**（**故意的**：比恢复时写两遍库便宜得多） |
| **声明完整性** | AST 扫真实节点源码，断言 **`interrupts` == 代码里真实构造 `InterruptRequest` 的节点集合** | 漏声明 ⇒ 装配期校验会被**空声明架空**（校验再严，声明为空就永不触发） |
| **红线本体** | 同文件 AST 用例：中断节点在 `InterruptRequest` **之前**不得有写操作 | 就是用户点名的那条 |

外加 **契约 6 可测化**：Service 层只许 import 运行时的 **12 个公开符号**（白名单），且不得 import 图定义模块
—— 因为「切换时要改的面」正好等于「Service 直接依赖的那些符号」。

### 关键设计取舍（写进代码注释与文档）

1. **扫描器必须带正反对照**：新增 `test_scanner_catches_deliberate_violations`（故意写违规代码，必须被抓到）。
   ⚠️ **「永远返回空列表的检查」比没有检查更危险** —— 它让人以为检查过了。
2. **误报会让守卫被删掉**：排除内存操作（`state.update(...)`）与 `logger.*`；
   提供 `# replay-safe: <理由>` 逃生舱（**必须写理由**且可复核）。
3. **只校验「声明自洽」，不校验 `entry` 是否注册** —— 后者在 `run_graph` 里有自己的失败路径
   （返回 `failed` 而不是抛），属**运行期**语义；混在一起会让运行期用例无法构造那种图。
